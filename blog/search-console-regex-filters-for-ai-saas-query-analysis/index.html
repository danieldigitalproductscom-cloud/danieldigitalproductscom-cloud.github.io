Search Console Regex Filters: Finding Real Opportunities in Your AI SaaS Queries

The default Search Console report shows thousands of queries in one undifferentiated list. For an AI/SaaS site, that list is dominated by your brand name, which hides the searches that tell you whether your content is actually working. Search Console supports regular expressions (RE2 syntax) in its query and page filters, and a handful of patterns turn the report into a decision tool. Everything below is free and takes minutes.

1. Where to find the regex filter

In the Performance report, click New (or the existing filter chip) and choose Query or Page. Change the match type from "Queries containing" to "Custom (regex)", then choose Matches regex or Doesn't match regex. Patterns are case-sensitive unless you start with (?i), so put that at the front of almost every query pattern.

2. Split branded from non-branded queries

Branded traffic is people who already know you. Non-branded traffic is where SEO earns new customers. Filter with Doesn't match regex:

(?i)acmeai|acme ai|acme\.ai

Include common misspellings and the spaced and unspaced versions of your name. Now compare clicks and impressions over 3 months against the previous period. If total clicks are growing only because branded clicks are growing, your content is not yet pulling in strangers, which is the first thing to know before you invest further.

3. Surface question queries

Questions reveal what people want explained and map well to FAQ sections and guides:

(?i)^(how|what|why|can|does|is|are|should|which|when)\b

Sort by impressions. Queries with many impressions and a position beyond 10 are topics you appear for but do not answer well. Either expand the existing page to answer that question directly in the first paragraph under a matching heading, or write a dedicated page if the intent differs from what you have.

3b. Find comparison and alternative intent

(?i)\b(vs|versus|alternative|alternatives|compare|comparison|competitor)\b

These are high-intent searches. If you see impressions for "[competitor] alternative" and have no page for it, that is a clear gap. If you have a page but it ranks at position 15, check that the title and H1 contain the exact phrasing.

4. Isolate commercial-intent modifiers

(?i)\b(pricing|price|cost|free|trial|demo|plans|review|reviews)\b

Compare the pages receiving these clicks with your pricing and demo pages. Often a blog post is catching a pricing query that should land on the pricing page. That is a prompt to add an internal link, adjust the post's call to action, or consolidate pages if two compete.

5. Filter pages by site section

Use the Page filter with regex to compare sections as groups:

  • Blog only: /blog/ (a plain "URLs containing" filter works too).
  • Feature and use-case pages: /(features|use-cases|solutions)/
  • Everything except the blog and docs: ^https://example\.com/(?!blog|docs) — RE2 does not support lookaheads, so for this use Doesn't match regex with /(blog|docs)/ instead.

That last point matters: Search Console uses RE2, which does not support lookaheads, lookbehinds or backreferences. If a pattern from a regex tutorial errors out, rewrite it with an inverted filter instead.

6. Find long-tail queries

Long-tail queries tend to convert better and are easier to win. Match queries with five or more words:

^(\S+\s){4,}\S+$

On a young site these often make up most of the non-branded impressions. Group them by theme. If twenty long-tail queries share one topic, that is a content cluster waiting to be built around a single strong page.

7. Spot wrong-intent and irrelevant impressions

Use a query filter to look for terms you do not want, for example "free download", "jobs", "course" or "tutorial pdf" if you sell software. Large impressions here mean a page is attracting the wrong audience. Tighten the title and description, or add clarifying language. It is also a reason not to chase every impression: a high-impression query with a mismatched intent will never convert.

8. Turn findings into a weekly routine

  1. Export the filtered tables (Export, then Google Sheets or CSV) so you can track changes, since the interface only keeps 16 months.
  2. Pick three actions per week: one question query to answer, one position 8 to 20 page to improve, one mismatched-intent page to retitle.
  3. Annotate the date and change in a simple log, then recheck in four to six weeks. Rankings take time to settle and changes made over days are hard to attribute.

9. Know the limits

Search Console samples and anonymizes rare queries, so totals across filters will not always add up. Data lags by a couple of days. Position is an average across devices and locations, so treat it as a trend, not an exact rank. And impressions from AI answer features are not separated out, so judge success by clicks and conversions, not impressions alone.

Quick checklist

  • Branded regex built, including misspellings, and used as an exclusion filter.
  • Question, comparison and pricing-intent patterns saved in a note for reuse.
  • Page filters set for each major site section.
  • RE2 limits remembered: no lookaheads, lookbehinds or backreferences.
  • Filtered data exported monthly to preserve history beyond 16 months.
  • Three concrete actions chosen each week, with dates logged.
